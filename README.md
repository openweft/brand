# openweft brand

Brand assets for the **openweft** organisation: the mark, its format matrix,
and the 1280×640 social banner that every `openweft/*` README puts at the top.

Generated by `logos/brandgen` from `openweft.svg`. Nothing here is drawn by
hand.

## Why this repository arrived late

Fifty-six `openweft/*` READMEs have referenced
`raw.githubusercontent.com/openweft/brand/main/social/…` since June. This
repository did not exist, so every one of them has been showing a broken image
at the top of the page.

The cause was not neglect. `openweft.svg` draws its glyph — three warp threads
crossed by a weft — with four `<line>` elements, and `gfx/svg` did not
implement `<line>`. A shape absent from its element switch is not rejected: it
is silently not painted. The banner generated, correctly sized and with its
wordmark, and simply had an empty space where the mark belongs, so it was
never published. Fixed in [go-gfx/gfx#47](https://github.com/go-gfx/gfx/pull/47),
which is also where the pixel test guarding it lives.

## ⚠ Still missing

Nineteen `openweft/*` repositories reference a per-repo declension that does
not exist yet:

```
weft-loom-{server,workspace,markdown,themes,texlive,cpp,golang,node,python,rust}
weft-loom-app-{linux,osx,windows}
weft-loom-theme-{cnrs,dinum,ihes,ip-paris,paris-saclay,polytechnique}
```

Those READMEs still show a broken image. The declension convention is the org
glyph shrunk into the top region plus a white name plate — **not** a new glyph
per repository — and the marks have to be drawn before they can be generated.

## Layout

| | |
|---|---|
| `svg/` | the mark, in colour, white and black |
| `png/`, `jpg/` | the format matrix, 16 → 1024 |
| `avatar/` | the org avatar |
| `ico/`, `icns/` | Windows and macOS icon containers |
| `social/` | the 1280×640 banner READMEs link to |
